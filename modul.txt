================================================================================
DOKUMEN SPESIFIKASI MODUL, STRUKTUR TABEL DATABASE, DAN FIELD
WEBSITE RESMI KARANG TARUNA KABUPATEN BANDUNG
(TERMASUK SISTEM WORKFLOW APPROVAL & MODERASI KONTEN MULTI-LEVEL)
================================================================================

Dokumen ini memetakan seluruh modul sistem informasi/CMS (Content Management System) 
dan perancangan basis data relasional (Database Schema & Fields) yang dibutuhkan 
berdasarkan fitur dan halaman-halaman yang telah dibuat pada antarmuka frontend,
dengan arsitektur:
1. Pemisahan MASTER REFERENSI WILAYAH MURNI vs MASTER LEMBAGA/UNIT KARANG TARUNA.
2. Mekanisme KONTRIBUTOR MULTI-TIER: Pengguna tingkat Kecamatan dan Desa/Kelurahan dapat menginput konten (Berita, Agenda, Prestasi, Galeri, Program Kerja, dan Data Warga PPKS), dengan sistem persetujuan (APPROVAL / MODERASI) oleh Pengurus Tingkat Kabupaten sebelum dipublikasikan ke publik.

================================================================================
MEKANISME WORKFLOW APPROVAL KONTEN (MULTI-LEVEL CONTENT APPROVAL FLOW)
================================================================================
1. Level Penginputan:
   - **Admin Desa / Kelurahan**: Dapat membuat draft konten Berita Kegiatan Desa, Agenda Desa, Foto/Video, Prestasi Pemuda Desa, dan Usulan Data PPKS.
   - **Admin Kecamatan**: Dapat membuat draft konten tingkat Kecamatan serta mereviu usulan dari Desa di wilayahnya.
   - **Superadmin Kabupaten**: Memiliki hak final untuk *Approve* (Setujui & Publikasikan ke Web), *Revision* (Minta Revisi), atau *Reject* (Tolak dengan catatan alasan).
2. Status Standar pada Setiap Konten Transaksional:
   - `draft`             : Konten masih disimpan secara privat oleh pembuat.
   - `pending_approval`  : Konten telah diajukan ke Kabupaten untuk direviu.
   - `approved`          : Konten disetujui Kabupaten & tampil aktif di website publik.
   - `rejected`          : Konten ditolak dengan catatan alasan penolakan.
   - `revision_required` : Konten dikembalikan ke pembuat dengan catatan perbaikan.

1. MODUL AUTENTIKASI & MANAJEMEN PENGGUNA (MULTI-LEVEL ADMINS)
--------------------------------------------------------------------------------

A. Tabel: `users`
Deskripsi: Menyimpan data pengguna / pengelola dari tingkat Kabupaten, Kecamatan, hingga Desa.
Field:
- id                      : BIGINT(20) UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
- name                    : VARCHAR(150), NOT NULL (Nama lengkap pengguna)
- email                   : VARCHAR(191), UNIQUE, NOT NULL (Email login)
- password                : VARCHAR(255), NOT NULL (Hash kata sandi)
- phone                   : VARCHAR(20), NULLABLE (Nomor WhatsApp/HP)
- avatar                  : VARCHAR(255), NULLABLE (Foto profil)
- role_id                 : INT(11) UNSIGNED, NOT NULL, FOREIGN KEY -> `roles.id`
- unit_id                 : BIGINT(20) UNSIGNED, NULLABLE, FOREIGN KEY -> `karang_taruna_units.id` (Unit Karang Taruna yang dikelola)
- can_auto_publish        : TINYINT(1), DEFAULT 0 (1 = Bebas approval/langsung terbit untuk Superadmin)
- is_active               : TINYINT(1), DEFAULT 1 (1 = Aktif, 0 = Nonaktif)
- remember_token          : VARCHAR(100), NULLABLE
- last_login_at           : TIMESTAMP, NULLABLE
- created_at              : TIMESTAMP, DEFAULT CURRENT_TIMESTAMP
- updated_at              : TIMESTAMP, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

B. Tabel: `roles`
Deskripsi: Master peran pengguna sistem.
Field:
- id                      : INT(11) UNSIGNED, PRIMARY KEY, AUTO_INCREMENT

================================================================================
RELASI ANTAR TABEL UTAMA (ENTITY RELATIONSHIPS)
================================================================================
1.  `ref_districts` (1) ---> (N) `ref_villages` (1 Kecamatan menaungi banyak Desa)
2.  `ref_districts` (1) ---> (N) `karang_taruna_units` (Unit KT tingkat Kecamatan ke Master Wilayah)
3.  `ref_villages`  (1) ---> (N) `karang_taruna_units` (Unit KT tingkat Desa ke Master Wilayah)
4.  `karang_taruna_units` (1) ---> (N) `unit_members` (1 Unit KT memiliki banyak Pengurus/Anggota)
5.  `karang_taruna_units` (1) ---> (N) `users` (Akun login admin per unit Karang Taruna)
6.  `users` (1) ---> (N) `articles` (User Kecamatan/Desa menginput berita dengan status pending approval)
7.  `users` (1) ---> (N) `events` (User Kecamatan/Desa menginput agenda kegiatan)
8.  `users` (1) ---> (N) `achievements` (User Kecamatan/Desa mengajukan usulan prestasi pemuda)
9.  `users` (1) ---> (N) `ppks_beneficiaries` (User Desa mengusulkan data warga penerima manfaat)
10. `users` (1) ---> (N) `content_approval_logs` (Admin Kabupaten mencatat riwayat review / approval)
11. `karang_taruna_units` (1) ---> (N) `work_programs` (Unit wilayah mengusulkan program kerja)
12. `photo_categories` (1) ---> (N) `photo_galleries` (Kategori foto ke galeri dokumentasi)
13. `download_categories` (1) ---> (N) `downloads` (Kategori dokumen ke file unduhan)
14. `ppks_categories` (1) ---> (N) `ppks_beneficiaries` (Kategori PPKS ke data warga)
